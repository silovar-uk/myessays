# 実験型記事パターン：Leaf Shield Lab

更新：2026-10-11

## 目的
通常の解説本文を残したまま、読者が「予測 → 操作 → 根拠 → 実機で再検証」できるページを追加する。ゲームの完全な物理再現を装わない。

初回実装：『スマブラSP』ロックマンのリーフシールド研究記事。
記事ID：ssbu-megaman-leaf-shield-four-leaves-commitment

## ファイルと役割
- assets/leaf-shield/mechanics.json：公開仕様・フレーム・更新履歴・出典
- assets/leaf-shield/scenarios.json：日本語／英語混じりの場面・選択肢・説明・検証課題
- reader-leaf-lab.js：表示、セッション状態、図、ドリル、ブラウザ内記録
- reader-leaf-lab.css：スマホ操作、余白、フォーカス、表示調整
- scripts/check-leaf-lab.mjs：ソースの静的な整合性検査
- .github/workflows/leaf-lab-check.yml：関連ファイルの更新時に検査
- index.html：CSSとJavaScriptの読み込み

## 読書モードへの接続
日本語正本にはHTMLのdiv要素（data-leaf-lab="ja"）を1つ、English Mixにはdata-leaf-lab="en-mix"を1つ置く。

Markdownの安全化処理はscript要素とstyle属性を禁止するので、本文に実行コードを埋め込まない。MyEssaysReaderRuntimeへleaf-shield-labという名前で登録し、描画後に機能を構築する。

必須条件：
- 対象記事ID以外にマウントしない。
- 日本語／English Mixを切り替えても、同一セッションのタブ・ドリル状態を保持。
- 読書メモ、読書位置、読了情報、切替UIを上書きしない。
- モバイル画面全体を覆う操作パネルを作らない。
- 公開仕様と推論・練習用の模式図を明確に区別する。

## 再現しないこと
- 実機の攻撃判定、被攻撃判定、移動速度、ふっとび、確定連係。
- 特定の対戦相手との勝率や反撃の確実性。
- 再ヒット間隔11Fを「11Fごとに必ず当たる」の意味として描くこと。
- 展開35F・追加保持約40F・射出55Fを足して絶対的な単一タイムラインとすること。

## データ保存・エクスポート
対戦記録はブラウザのlocalStorage（myessays:leaflab:entries:v1）に最大80件保存。言語切替後も共通。
ユーザーは削除でき、CSVを保存・コピーできる。入力は長さ制限し、画面出力時にはHTMLをエスケープする。
クラウド同期なし。端末のブラウザデータが消えると記録も消える。CSV出力以外の理由で記録をサーバーへ送信しない。

## 実装した機能
1. 相手を変える：6つの典型状況、模式図、3択、理由と例外の確認。
2. 1Fずつ見る：展開・追加保持・射出を分けたフレーム観察、公開仕様。
3. 時代を変える：『ロックマン2』→『スマブラfor』→『スマブラSP』初期→更新後。
4. 判断ドリル：6問をランダムな順で出題し、考え方と根拠を確認。
5. 対戦記録：状況・結果・任意メモの保存、集計、CSV出力・削除。

## 受け入れ検査
静的テスト：node scripts/check-leaf-lab.mjs

ブラウザではデスクトップ／iPhone Safariで次を確認する：
- タブ切替・横スクロール・レンジ入力が操作可能。
- 模式図・操作ボタンが画面からはみ出さない。
- 解説表示後、場面を切り替えると選択状態が初期化される。
- 言語切替でも進行中のドリル状態が維持される。
- CSVに引用符、カンマ、改行が入っても列が壊れない。
- ほかの記事の目次・読書メモ・読了記録へ影響しない。
- ブラウザ保存ができなくても本文を読める。
- モーション削減設定では過剰な動きを避ける。
- データ取得に失敗した場合は本文を残し、出典リンクを示す。

## 再利用に向けた設計判断
記事固有のコードを直ちに共通化しない。まず実地で学習効果・操作性を検証し、安定した機能だけを汎用的な「フレーム観察」「選択と条件反転」「検証ログ」へ切り出す。ほかのゲームやスポーツへの拡張でも、測定値と推論の境界を守る。

## UX改修（2026-10-11、第二版）
最初の版では入口に5タブを同時表示し、読者に「どれを触るか」を判断させていた。研究資料としては十分でも、遊びながら理解する最初の10秒が弱かった。

改修では、冒頭の一文の直後に体験を配置し、最初に表示する操作を「Bを長押し」に限定した。スマホで直接押し続けるポインター操作と、長押しが難しい場合の「タップで保持」ボタンを併設。途中で指を離すと発射、限界まで離さないと自動発射という違いを簡略化した時間モデルで視覚化する。約76Fの進行は公開データの時間感覚を学ぶための演出で、実機の動作状態機械や正確な発射時刻を再現するものではない。

従来の5機能は消さずに「もっと調べる」を押したときだけ表示する。記事を読む人には文章と操作を短い距離で行き来してもらい、研究を深めたい人には従来のモードを残す。

追加検証：マウス／タッチの押下・離上、キーボードのEnter／Space、保持固定ボタン、途中発射・自動発射、advanced表示の初期閉状態、版切替での状態保持をテストする。実際のiPhone Safariでの視覚・ジェスチャー受け入れ確認は、デスクトップの模擬テストと区別する。
