# MyEssays 流して読む｜見出し後の読み落とし対策（2026-10-24）

## 1. 守：観測された問題と現行構造
- ユーザー報告：小見出しで一度止まると、直後の本文が目に入りづらい。
- コード上の事実：`reader-rsvp.js` は H2=1300ms、H3=800ms のカードを表示し、その直後は通常の文節表示へ移る。RAMP=[1.5,1.25,1.1] は新規再生の最初の3文節に作用するが、各見出しごとには再開しない。
- 見出しは意味内容の切替点。通常の単語や読点と異なり、読者は読書の文脈を更新する必要がある、というのが今回の設計仮説。
- 外部資料：
  - Rayner et al., 2016: https://journals.sagepub.com/doi/10.1177/1529100615623267
  - Acklin & Papesh, 2017: https://pubmed.ncbi.nlm.nih.gov/29461715/
  - NN/g Layer-Cake Scanning, 2019: https://www.nngroup.com/articles/layer-cake-pattern-scanning/
  - W3C WCAG 2.2.2 Pause, Stop, Hide: https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide
- これらの文献は「650ms・500ms」という固有の設定値を検証したものではない。

## 2. 破：今回実装した最小の改善
1. H2/H3直後の最初の2文節だけ、本文表示時間を延ばす。
   - 1文節目：従来算出時間 +250ms、かつ最低650ms。
   - 2文節目：従来算出時間 +140ms、かつ最低500ms。
   - 3文節目から通常速度へ戻る。
2. 該当文節の間は既存の小さな「現在の見出し」欄を読める濃さに保つ。
3. H3も「現在の見出し」に採用し、H2だけに戻ってしまう不整合を解消する。
4. 図・コード・表が間に入れば章頭ブレーキを解除する（図は従来の手動再生待ちが優先）。
5. 時間は同じ `retime` の中で計算し、残り時間推定に反映。再計算時に加算が累積しない。
6. 利用者に新しいスイッチを増やさない。既存の再生・一時停止・速度設定・文単位の移動は変更しない。

## 3. 次のリサーチ計画と再検証（実ユーザー環境）
まず iPhone Safari を中心に、同一記事の H2/H3 を5回またぐ実地操作で見出し直後の本文を認識できた割合を記録する。速度条件は600字/分・2000字/分・4000字/分。特に4000字/分は最低表示時間による減速の違和感も評価する。

対照条件：修正前の流し読みと修正後で同じ記事・同じ速度を比較する。読む記事の順序を入れ替えて順序効果を減らす。

一次データ：
- 次の見出しを通過した直後、その節の最初の文節を再現できたか
- 見出し直後に巻き戻し操作が生じた回数
- リズムの違和感（5件法）
- 読了までの経過時間（特に見出し数が多い記事）
- iPhone Safari のレイアウト、表示位置、タップ一時停止、画面回転
- 日本語／English Mix切替後の再生の起点、図の手前・後、参照文献への到達

受け入れ条件（仮の目標値）：通常設定の600字/分で「最初の文節の読み落とし0/5」、巻き戻し不要、従来の制御に不具合なし。高速設定では好みの差が大きい可能性があるため固定閾値を強要しない。

実施済み検査と未検証を分離する：
- 実施済み：GitHub上のJS/CSSと読み込み指定の整合性の静的確認。
- 追加済み：`node tools/test-rsvp-section-entry.mjs` によるH2/H3、図による解除、再計算の冪等性の回帰テストコード。
- 追加済み：関連ファイル変更で上記を実行するGitHub Actions workflow。
- 未検証：GitHub Actionsの実行結果、iOS Safari上の実レンダリング、被験者による理解度。確認前に「効果を実証済み」と書かない。

## 4. 離：発見が続く流し読み（追加実装）
最初の「見出し直後の減速」を土台に、次の3つを後続のコミットで実装した。

### 4-1. 予告：次の話題を知らせる
- H2/H3の見出しカードに静かな「NEXT · 次の話題」「次の小見出し」の案内を加えた。
- 内容をAIで生成・要約せず、元記事の見出しをそのまま利用。真偽や言い換えによるズレを防ぐ。
- 見出し直後の2文節だけ減速し、上部に節名を残す。

### 4-2. シーン再生：前後の意味を一緒に読む
- 表示設定の「流し方」で **文節 / シーン** を選べる。
- シーンでは同一文・同一段落内の最大3文節を同時に表示。現在位置を強調し、前後は弱めに表示。
- タイミングと再生位置は既存の文節配列をそのまま使用する。本文への復帰、段落ロケーター、残り時間、速度変更、句読点休止、日英切替に影響しないことを目指した。
- 初期値は既存の「文節」。横書き・縦書きの両方のCSSを設けた。
- 設定ショートカットは `M`。

### 4-3. 発見の保存：原文へ戻れる振り返り
- 再生画面下部の「☆」で現在の文を保存、再度押すと解除。キーボードでは `B`。
- 保存は端末の `localStorage` に `myessays:rsvp-discoveries:v1` で格納。
- 各保存には記事ID、言語、段落ロケーター、対応ID、文頭位置、原文の短い引用を含める。
- 1記事24件まで。見出し・図・読了画面では保存操作は無効。
- 保存した項目は読了カードと本文下部の「流し読みで見つけたこと」に表示。クリックすると原文の段落へ戻る。本文が差し替わったときはロケーター、次に対応IDで探す。
- 保存済みの発見がある場合、読了カードを短時間で自動的に閉じず、自分で「読後へ」を押せる。
- クラウド同期・端末間同期・アカウント登録は追加していない。ブラウザーのサイトデータ消去で保存内容も失われる。

### 4-4. 外した案
- 自動生成による「驚きの疑問」：記事にない前提を生みやすいので見送り。
- 紙吹雪・通知・ポイント：読書に不要な刺激を増やすため見送り。
- 毎章のクイズ：任意の振り返りより操作負担が大きく、未実装。
- 全員にシーン再生を強制：現行の文節方式を好む読者がいるため見送り。

## 5. 回帰テストと受け入れ条件
- `tools/test-rsvp-section-entry.mjs`：章頭の減速、再計算の冪等性、H2/H3、図の停止。
- `tools/test-rsvp-experience.mjs`：シーンの単位境界、原文の引用、保存キー、レイアウト構成・読み込み指定。
- `.github/workflows/check-rsvp-section-entry.yml`：上記2テストとJavaScript構文検査。
- 実施済み：GitHub内コードの構文検査、タイミング・シーン区分ロジックを独立評価、ソース整合性確認。
- 未確認：GitHub ActionsでのNodeテスト実行結果、iPhone Safari実機の描画、音声読み上げ、読み落とし率と理解度の計測、GitHub Pagesのキャッシュ反映。
- 実機で重点確認：iPhone SEクラスの狭い画面、縦書きシーン、超高速設定、シーン中の途中再開、保存後の元本文への復帰、日英切替、図の前後、読了画面での発見カードのタップ。

## 6. 対象ファイル
- `reader-rsvp.js`：再生・シーン分割・発見データの保存／復元・読了カード
- `reader-rsvp.css`：シーン表示、控えめな予告、保存ボタン、読後一覧、スマホ表示
- `index.html`：スクリプトとスタイルのキャッシュ更新
- `tools/test-rsvp-section-entry.mjs` / `tools/test-rsvp-experience.mjs`：回帰テスト
- `.github/workflows/check-rsvp-section-entry.yml`：自動検証
