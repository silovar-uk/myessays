# Ulm School――デザインを「完成品」ではなく「判断の仕組み」として見る
## Design Literacy #16｜Method, System, and Critique

**Design can be more than the shape of an answer. It can be a method for making decisions.**

これまでGridではspatial rules、Similarityではvisual grouping、Fitts’s Lawではmovement to a targetを見てきた。

This time, we zoom out again. そもそもdesignを「個別の形をつくる行為」から、**a way to structure repeatable decisions**へ広げると何が起きるのかを見る。

中心に置くのは、1953年から1968年までドイツで活動した**Hochschule für Gestaltung Ulm / HfG Ulm**だ。

## 1. まず一言：Design the way decisions are made

ボタンを一つ作るなら、

```text
Button
↓
color
radius
font
padding
```

というobject-level decisionsで済む。

But once screens multiply, the question changes.

```text
Primary
Secondary
Danger
Disabled
Loading
↓
What stays the same?
What changes?
Which states exist?
Who reuses the rule?
```

ここでは「このボタンをどう見せるか」だけでは足りない。

**How should future decisions be made?**

次のscreen、次のdesigner、次のmediumでも判断を再現できるよう、rule itselfを設計する必要が出てくる。

Ulmを見る面白さは、このshiftを歴史の中で考えられることにある。

## 2. 仕組み：Practice and theory were taught together

HfG Archivによれば、Ulmではfive fieldsでdesignerを育成していた。

- **Product Design** / 製品造形
- **Visual Communication** / 視覚コミュニケーション
- **Building** / 建築
- **Information** / 情報
- **Film** / 映画

The four-year program combined departmental design practice with theoretical subjects needed for design work.

[HfG-Archiv Ulm — Die HfG](https://hfg-archiv.museumulm.de/geschichte-hfg/)

ここで重要なのは、design educationを「手を動かしてformを作る訓練」だけに閉じなかったこと。

```text
making
+
analysis
+
theory
+
technology
+
social context
```

を横断しながら、**what kind of profession “designer” should be**まで実験された。

So Ulm is easier to understand not as a school that produced one visual style, but as a school that kept asking how design decisions could be learned, explained, and repeated.

## 3. Before → After：From one-off decisions to reusable decisions

### BEFORE

画面ごとに、その場で決める。

```text
Screen A
[購入する] red / 48px / radius 8

Screen B
[送信する] blue / 44px / radius 4

Screen C
[予約する] black / 52px / radius 12
```

All three are Primary Actions, but every decision is isolated.

### AFTER

先に「Primary Actionとは何か」を定義する。

```text
Primary Action
↓
color role
height range
typography
spacing
states
interaction feedback
accessibility condition
```

Then the rule is applied to multiple screens.

```text
Rule
↓
[購入する]
[送信する]
[予約する]
```

ここで変わったのは、単にappearanceが統一されたことではない。

**One-off decisions became reusable decisions.**

個別判断が、future workへ渡せる判断になった。

## 4. そのまま使える制作・修正指示

レビューなら、こう言える。

> **個別画面の見た目を直接そろえる前に、同じ役割を持つ要素に共通する判断ルールを定義してください。色・余白・タイポグラフィ・状態・操作・アクセシビリティ条件を分け、別画面や別担当者でも再利用できる形にしてください。**

In English:

> **Don’t solve this only as a one-off screen. Define the reusable decision behind the screen.**

そして、もう一問。

> **Is this a one-time decision, or a rule we want to reuse?**

ただし、everything should not become a rule. その理由がUlmの歴史へつながる。

## 5. 歴史との接続：Ulm systematized design—and argued about systematization

Ulmはよく、rational and scientific design methodologyを代表する学校として語られる。

That is not entirely wrong, but it is incomplete.

HfG Archivは、1960年代に教育の**scientification**が進み、Horst Rittel、Hanno Kesting、Bruce Archerらのもとで、mathematical operationsを意識したstrict methodologyや、ergonomics、company analysisなどのanalytical studiesが強まったと説明している。

At the same time, this direction caused major internal conflict. Otl Aicher、Hans Gugelot、Walter Zeischegg、Tomás Maldonadoらは、**design had to be more than analytical method alone**として、過度なscientificationへ異議を唱えたと記録されている。

[HfG-Archiv Ulm — Geschichte](https://hfg-archiv.museumulm.de/geschichte-hfg/geschichte/)

ここが重要。

```text
Ulm
≠ science replaced creativity

Ulm
= design was methodized
  AND
  the limits of method were debated
```

So the historical lesson is not simply “systematize everything.”

**Methods themselves must remain open to criticism.**

方法そのものも、目的に合っているか問い直される必要がある。

## 6. Visual Identityとの接続：Design rules can travel into future work

One well-known Ulm-related example is Lufthansa’s visual identity.

HfG Archivによれば、1961〜62年、Otl Aicherが率いるdevelopment group E5はLufthansaのsystematic visual identityを設計した。Aicher archiveにも、Lufthansaを含むE5 projectsが記録されている。

[HfG-Archiv Ulm — From Logo to Identity](https://hfg-archiv.museumulm.de/en/exhibition/from-logo-to-identity-visual-appearances-of-the-federal-republic-of-germany/)

[HfG-Archiv Ulm — The bequest of Otl Aicher](https://hfg-archiv.museumulm.de/en/bequests/the-bequest-of-otl-aicher/)

Visual Identityでは、one logoを完成させれば終わりではない。

```text
mark
+
type
+
color
+
layout
+
signage
+
application rules
```

複数媒体でsame organizationとして認識できるよう、**future artifacts that do not yet exist**にも判断を渡す必要がある。

This is structurally similar to a modern Design System.

ただし、**Ulm or Lufthansa identity = the direct origin of today’s Design System**とは断定しない。technology, organization, media, and development processes are different.

The useful connection is the problem structure: **designing reusable rules instead of only a single artifact.**

## 7. 誤解しやすい点：Systemization does not guarantee good design

ルールが増えれば、consistencyは上げやすい。

But a bad rule also scales.

```text
bad rule
×
100 screens
=
100 consistent problems
```

だからDesign System reviewで、

```text
Is it consistent?
```

だけを見るのは足りない。

Ask instead:

```text
Why does this rule exist?
Who benefits from it?
Where should exceptions be allowed?
Can the rule be changed?
```

**Consistency is not evidence of correctness.**

一貫していることは、正しいことの証明ではない。

Ulm内部でmethodology自体が論争になった歴史は、このpointをかなり強く思い出させてくれる。

## 8. 以前の学びとの接続：Don’t just use rules—question them

これまでの学びを並べると、

```text
Grid
= spatial rule

Similarity
= perceptual rule

Tap Target / Fitts’s Law
= interaction rule
```

まで来た。

Today we add another layer.

```text
Ulm
= combine decisions into methods
  +
  question the methods themselves
```

ここで前より解像度が上がる。

**A design system is not just a collection of reusable decisions. It also needs a way to challenge and update those decisions.**

Design Systemは再利用可能な判断のcollectionだけでは不十分で、**a mechanism for questioning and updating the rules**まで必要になる。

## 9. 30秒でできる観察

Open one service and compare three similar screens.

探すのは、

```text
same spacing
same button
same heading
same icon
same error state
```

Then ask two questions.

**“Is there a shared rule behind this?”**

次に、

**“Is that rule actually right for this situation?”**

前者がsystemを見る目。
後者がsystemを批判する目。

You need both.

## 10. 次につながる概念：Design Tokens / Governance

Next comes **Design Tokens**.

```text
spacing-sm = 8
spacing-md = 16
radius-md = 8
color-action-primary = ...
```

When design decisions become data, rules can travel more easily into code and across platforms.

でも今日のUlmを経由したあとなら、another set of questions appears.

```text
Who defines the token?
Who can change it?
Why does it exist?
```

That leads to **Governance**.

ルールを作ることと、rulesを運用・改訂することは別の問題や。

---

**Today’s claim:**

**Design can systematize decisions, but good design also questions the system.**

日本語なら、

**デザインは「判断を仕組みにする」だけではない。その仕組み自体を疑い、更新することまで含む。**

Ulmを“the rational design school”とだけ覚えると半分。

They built methods—and argued about whether method alone was enough.

そこまで見ると、60年以上前のschoolの話が、いまのDesign System reviewへつながってくる。
